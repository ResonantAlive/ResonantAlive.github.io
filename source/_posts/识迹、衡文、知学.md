我们很高兴开源 writing_modify，这是我们开源的第 12 个项目。
选择题有标准答案，对就是对，错就是错：一位老师一小时能批完 200 份选择题，却往往批不完 20 份作文。
原因在于作文是主观的。主观意味着评分会受老师的评分风格、当天的心情，甚至疲劳程度影响：同一位老师上午和深夜的尺度可能不一样，不同老师之间差异更大。批得慢，结果也不一定好。
我们的解决方法：用 few-shot 让模型学会"你的"尺度
我们没有去训练或微调模型，而是采用 few-shot（少样本学习）：
老师先认真批改 5～10 份作文：打分，也可以写意见条目；
系统把这些复核过的作文作为示范放进提示词（默认每次最多 3 份，可配置）；
大模型按同样的尺度批改其余作文；
老师只需复核：一键采纳 AI 的结果，或者改分、补充意见。改过的结果会成为之后批改的新示范。
整个过程低成本、无需训练，换一批题目、换一位老师马上就能用。示范默认只取自你自己的批改，不会混入别人的数据。在示范和大模型本身能力的加持下，批改结果更稳定、更一致，老师可以把时间花在真正需要判断的作文上，而不是逐份从头批。
一条完整的流水线
上传作文照片 → 分成一篇篇作文 → 识别手写 → 大模型批改 → 老师复核 → 批次汇总与共性问题报告 → 通过 API 接入你的系统
功能一览
两条识别路线：本地 OCR（PP-OCRv6，手写识别在你自己的机器上，只把文字发给大模型，不发照片），或者让视觉模型直接看图。
答题纸模板：先上传同款空白答题纸，系统记住纸上的印刷内容（标题、页边提示、条形码、页码），识别作文时自动去掉，不会混进作文里。
保留学生的拼写错误：识别不会替学生"改对"，这对批改语言分很重要。
批量处理，可暂停、可恢复：失败比例过高或接口连续出错时自动暂停，不会把整批作文白白烧掉。
教师复核：一键采纳、改分、写意见条目；每次修改都新增一版历史，旧版本和 AI 的原始结果不会被覆盖。
批次汇总和共性问题报告：见下面的 QA。
数据留在自己手里：批改数据都是磁盘上的普通文件（JSON 加原图），API key 只保存在服务器上；账号之间严格隔离，别人的数据一律访问不到；默认只监听本机。
QA
1. 看不到学生的闪光点和整体共性错误怎么办？
我们在设计时考虑到了这点，并把它加进了 v1：
每篇作文的批改结果里有判据和评语。想要单篇的闪光点，可以在提示词模板里要求模型写出来。
批次完成后，可以一键生成"共性问题报告"：汇总全班集中出现的问题（几篇出现、典型表现、涉及哪几篇）、给老师的讲评建议，以及整体优点。
生成报告只发送题目、评分标准和各篇的评价文字，不发送作文原文和照片。
2. 我已经有了相关工作台，或者其他 AI 写的软件了，怎么把 writing_modify 的批改数据接入进去？
我们采用"万物 API"的设计：writing_modify 自己的前端用的就是同一套 REST API（/api/v1）。每个账号都可以签发自己的 API 令牌（Bearer），令牌的权限不会超过账号本身。用它就能上传作文、创建批次、读取批改结果、提交复核。
批改数据也是磁盘上带版本号的 JSON 文件（复核记录、批次汇总、共性报告），可以直接读取。所以你只需要改动现有工作台的一小部分代码，就能把 writing_modify 合并进你的工作流。
3. 我的数据会被发到哪里？
本地 OCR 路线只会把识别出的文字发给你选择的大模型服务商，不发照片；视觉路线会发送照片。服务商是你自己配置的。如果它不是本机地址，第一次使用前系统会要求你明确确认。本软件不会自动向我们上传任何数据。
4. 批改得准吗？
结果取决于你选的模型和你给的示范质量。每篇作文会同时记录 AI 分和老师最终分，批次汇总里有两者的平均差，你可以用自己的数据来检验，再决定放手到什么程度。

现状与局限（v1）
目前面向英语作文。
需要自备大模型服务（兼容 OpenAI 接口格式的服务商即可）。
v1 不提供删除功能；需要删数据时，先停止服务，再手动删除对应目录。
本地识别需要 Python 环境和 OpenVINO；第一次使用要把模型导出一次（约 30–45 秒），导出需要 torch 和 transformers。PP-OCRv6 的模型权重（来自 PaddleOCR，Apache-2.0）已随仓库提供，克隆后无需另外下载。
我们还没有公开的准确度基准评测。
开始使用
仓库：https://github.com/ResonantAlive/En-writing-modify（Apache-2.0）
需要 Python 3.12：
git clone https://github.com/ResonantAlive/En-writing-modify.git
cd En-writing-modify
python -m venv .venv
# 激活虚拟环境：Windows 用 .venv\Scripts\activate，macOS / Linux 用 source .venv/bin/activate
pip install -r requirements.txt
python start.py

注：没有git可以自己去Github下载压缩包，解压放在你选择的目录即可（然后跳过git命令，继续执行下面的）/ .venv环境是可选的，如果你不愿意使用虚拟环境，您可尝试直接pip
start.py 不会自己切换 Python，请先激活装好依赖的虚拟环境再运行。macOS / Linux 如果没有 python 命令，请用 python3。
只用视觉模型路线，做完上面几步就够了。要用本地识别路线，还需要再装 torch 和 transformers（pip install torch transformers），用来把 PP-OCRv6 导出成 OpenVINO 模型。导出只做一次，生成的 data/ov_models/ 可以直接拷到别的机器。权重已经包含在仓库里（约 157 MB，所以第一次克隆会稍慢），不需要另外下载。
更详细的说明见仓库里的 README。
