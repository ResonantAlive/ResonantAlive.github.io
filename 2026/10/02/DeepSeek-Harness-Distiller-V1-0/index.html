DeepSeek-Harness-Distiller-V1.0

开源 DeepSeek-Harness-distiller：为 Agent 训练数据而生的教师模型轨迹蒸馏

我们很高兴开源 DeepSeek-Harness-distiller。这是我们为接下来Cealum系列最大最强模型所开发的Agent蒸馏工作流。

本项目基于 DeepSeek-Harness，修改了部分代码，为 Linux 环境做了部分适配。在原版之上，我们加了一套完整的「教师模型轨迹蒸馏」能力：让强模型在真实任务里自己干活，把整个过程安全、可追溯地录下来，最后产出一份带标签、可直接用于训练的数据集。

为什么？

想蒸馏一个 Agent，光有对话记录是不够的。我们很难知道：

  • 任务到底成功了没有？ 需要客观的判定。
  • 命令执行的结果是什么？ 模型看到的是一段合并后的文本，但数据集需要机器可读的退出码、分离的 stdout/stderr，以及进程是否被信号终止。
  • 录下来的东西能安全落盘吗？ 密钥、令牌不能进入数据集。

并且，让一个仅仅几B参数量的模型通过RL自己发掘正确的道路是非常困难的，算力开销很容易就达到研究员无法承受的程度

因此，蒸馏便成为最好的选择。

How to work？

整套能力由五个新包和一个新应用组成。

五个包（packages/distill/）

包 职责
redaction 落盘前把密钥替换为占位符，覆盖原文、blob、轨迹和归档会话
teacher-lock 在加载时拒绝任何可能服务非锁定模型的组合
trajectory-events 订阅会话与流事件，写出脱敏的原始事件日志和内容寻址的 blob
distill 加载任务定义、运行独立尝试、客观判定、写出带标签的数据集
resource 探测容器实际允许的 CPU/内存，拒绝装不下的切分方案

一个应用（apps/distill/）

  • composition.ts：通过 Cordis Loader 组装，而不是手搭插件
  • agent-runner.ts：生产级 AgentRunner，负责建会话、发消息、带超时地等待空闲、落盘
  • bin.ts：命令行入口，包含参数解析、限流、资源校验和逐任务执行

启动方式是一个新的 profile：dsh --profile distill。

改动

改核心代码是有风险的，所以…

原版手写源码只改了 6 个文件、约 120 行，全部是加法，没有删除，也没有改变原有行为。

  1. llm/src/types.ts：给流式协议的 usage 分片加了可选字段 servedModel，用来记录实际服务请求的模型。
  2. llm-deepseek/src/translate.ts：原版把响应里的 message.model 丢掉了，我们把它读出来并透传。这是上一条的数据来源，只有适配器知道这个信息，插件层拿不到。
  3. tool-bash 和 tool-pwsh：新增 presentationMeta 投影，把退出码、信号、超时、分离的 stdout/stderr 等结构化信息写入模型不可见的工具结果元数据。ToolResult.meta 是框架已有字段，所以不改模型输入，也不会触发快照变更。
    两个都要改，是因为真实 API 测试暴露了一个问题：模型在 Windows 上用的是 pwsh。只改 bash 的话，Windows 主机上的终止信息采集会全部为空。
  4. app-boot/src/index.ts：把 distill-teacher-lock 加入「必须成功启动」名单。教师锁拒绝启动时，应用必须停机，否则会录出一整份归属错误的轨迹。我们的原则是：配置错误要大声失败，而不是静默跳过。
  5. app-boot/src/profile.ts：注册 distill profile。

另有两个生成产物（Cordis 服务目录和插件包清单），由生成器重跑，无需手改。

除此之外，所有能力都以新增插件的方式实现。

不知道写什么标题

教师锁在加载期生效。 它不是运行时的软检查，而是在启动装配里强制：不确定能保证是锁定模型，就不启动。

先脱敏，再落盘。 脱敏覆盖原文、blob、轨迹与归档会话。

判定是客观的。 任务的判据由任务定义给出。为了防止作弊，我们在运行前后对判据做指纹比对，篡改会被发现。

资源切分基于真实限制。 resource 包探测的是容器实际允许的 CPU 和内存，而不是宿主机的数字，装不下的切分方案会被直接拒绝。

验证情况

项目 结果
文档门禁 pnpm run doc-sync 43 / 43 通过
五个新包的覆盖率门禁（per-file 100%） 5 / 5 通过
新增包与应用单测 355 通过
真实 API 端到端 3 / 3 通过
tsc -b tsconfig.host.json exit 0
tool-pwsh 自身测试 100 通过

真实 API 的三个用例覆盖了三类结果：判定成功、判定永不通过、预算超限。

快速上手

有一点需要注意：应用运行的是 lib/ 产物，修改 src/ 后需要先执行 pnpm run build:lib:host 重新构建，真实链路才会生效。

已知限制

  • 判据进程没有独立沙箱。 评估器与 runner 同进程，防作弊依赖指纹比对，能发现篡改，但没有进程隔离。
  • thinking 开关尚未记录。 它位于适配器的线格式中，不在 LlmCallConfig 里。目前轨迹记录的是 reasoning_available，即是否实际拿到了思考内容。
  • 尚未实现： 会话日志的脱敏销毁、崩溃恢复、配置优先级链。
